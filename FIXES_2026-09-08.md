# IFC Academy - إصلاحات 2026-09-08

تم إصلاح مشاكل الحفظ والاستيراد التالية:

- إصلاح إضافة اللاعبين عند تكرار رقم العضوية `member_number`؛ السيرفر ينشئ رقم IFC فريد تلقائيًا ويعيد المحاولة عند تعارض UNIQUE.
- استبدال `upsert` الخاص بإضافة اللاعب بـ `insert` حتى لا يؤدي فشل رقم العضوية إلى تعديل لاعب موجود بالخطأ.
- استيراد Excel للاعبين أصبح يدعم عناوين الأعمدة العربية والإنجليزية، بما فيها ملف التصدير العربي من الأكاديمية.
- إصلاح قراءة تواريخ Excel وتحويلها إلى `YYYY-MM-DD` بدل تخزين أرقام Excel التسلسلية.
- الاستيراد يعالج كل صف على حدة ويحسب عدد الصفوف المحفوظة والمتخطاة والفاشلة بدل إيقاف العملية كلها عند أول خطأ.
- رسائل أخطاء API أصبحت تعرض رسالة السيرفر/قاعدة البيانات الحقيقية بدل رسالة عامة.
- إضافة Toast نجاح متناسق مع واجهة النظام عند إضافة/تعديل لاعب وعند نجاح استيراد اللاعبين.
- إصلاح إضافة المدرب بحيث لا يظهر في الواجهة قبل نجاح الحفظ في قاعدة البيانات.
- حماية أرقام الإيصالات من تعارض UNIQUE عند التكرار.
- تمرير قائمة اللاعبين الحالية إلى نافذة إضافة اللاعب لتقليل تعارض أرقام العضوية قبل الإرسال.

لا توجد تغييرات مطلوبة على Schema قاعدة البيانات لهذه الإصلاحات.

## Settings hardening - 2026-09-08
- Replaced browser `alert()` calls in the application source with the unified IFC system toast event.
- Settings backup/restore now uses Excel (`.xlsx/.xls/.csv`) instead of JSON.
- Full Excel backup exports separate Arabic sheets for players, payments, expenses, coaches, and settings.
- Full Excel import accepts Arabic/English sheet and column names and persists records through the existing Supabase API, followed by a database reload.
- Settings reset is now a real, authenticated database operation: it clears operational academy data (sessions, payments, expenses, coaches, players, monthly archives) while preserving admin credentials and academy settings.
- Reset clears local caches and reloads authoritative Supabase state.
- Settings save now reports Supabase success/failure through the unified toast.
- Remaining browser `confirm()` dialogs are intentionally preserved where destructive actions require an explicit confirmation; they are not `alert()` popups.

## 2026-09-08 Session + Excel Import Hardening
- Added automatic Supabase session refresh and one-time retry for every authenticated API request after HTTP 401.
- Added concurrent refresh locking to prevent multiple refresh calls from racing.
- If refresh is no longer possible, authentication tokens are cleared and the app returns to the login screen.
- Prevented authenticated GET requests from silently falling back to stale local cache after an expired session.
- Excel imports now prefer the correct worksheet by page (Players/Payments/Expenses/Coaches/Attendance) instead of always taking the first sheet.
- Added direct Coaches and Attendance import handlers to the corresponding pages.
- Attendance import resolves players by internal ID, member number, or exact name and updates/inserts individual sessions without replacing the player's existing attendance history.
- Player import can resolve an existing player by member number server-side when an internal ID is absent, preventing duplicate players on repeated imports.
- Improved Excel number/date handling, including Arabic-Indic numerals.
- All toolbar exports labeled as Excel now generate real `.xlsx` workbooks instead of CSV files.

## Legacy Supabase schema compatibility
- Fixed player creation/import for older Supabase `players` tables that do not yet have `birth_date`.
- The server retries a player write without `birth_date` when PostgREST returns `PGRST204` for that column, so adding a player no longer fails.
- `sql/supabase_schema.sql` now contains a non-destructive `ADD COLUMN IF NOT EXISTS birth_date` migration for installations that want the birth-date field persisted.
- The player modal now waits for the database save result before closing.
